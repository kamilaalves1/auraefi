# Discovery practices

## Product lane

- Frame problems as **observable user behavior**, not feature lists.  
- Each initiative: **hypothesis → signal → next experiment**.  
- Acceptance criteria: **given / when / then**, plus negative cases.

## Analysis lane

- Separate **facts** (logs, tickets, metrics) from **interpretations**.  
- Document **constraints**: regulatory, budget, timeline, integrations.  
- Prefer **journey maps** or **sequence notes** over long prose.

## Facilitation lane

- Timebox discovery; default **vertical slice** over horizontal “all APIs first.”  
- Make dependencies visible: **who waits on whom**.  
- End each session with **decisions**, **owners**, **due dates**.

## Prioritization lane

- Stack rank with **cost of delay** and **risk reduction**, not loudness.  
- Say **no** by deferring to a named future bucket, not by ignoring.  
- Protect **refactor budget** when complexity interest is compounding.
